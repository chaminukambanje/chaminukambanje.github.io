📊 Dataverse Data Modeling: Tables, Columns & Advanced Attributes

Dataverse is not just a database; it is a full relational data service with built-in business logic, auditing, and role-based security.

1. Column Types & Mathematical Computation

Column Type Evaluation Mechanics Key Constraints & Behavior
Choice (Single-Select) Stores a single selected integer code mapped to a localized string label. Can be Local (specific to one table) or Global (shared across multiple tables like 'Country Code').
Choices (Multi-Select) Allows users to pick multiple options stored as a semicolon-delimited string of values. Cannot be used in Rollup calculated column criteria. Supported in Canvas apps via Concat().
Calculated Columns Computed on-the-fly at the time of retrieval (read-time). Supports basic math, string manipulation (CONCAT, TRIM), and date math (ADDDAYS, DIFFINDAYS). Does not support aggregates.
Rollup Columns Asynchronously aggregates child records across a 1:N relationship. Supports SUM, COUNT, MIN, MAX. Recalculated periodically (every 12 hours) or manually via Mass Calculate. Cannot reference another rollup column.

2. Business Rules

Business Rules allow functional consultants to implement client-side validation and form logic without writing JavaScript:

  • Scopes:
    • Single Form: Executes only on that specific form.
    • All Forms: Executes across all forms for that table in Model-Driven apps.
    • Entity (Table): Executes both on the client UI AND server-side (enforced during API/Power Automate updates).
  • Supported Actions: Set field value, Clear field value, Set field requirement level (Mandatory/Optional), Show error message, Lock/Unlock field, Set default value, Show/Hide field.

🔒 Enterprise Security: Business Units, Teams & Roles

Business Unit Architectures

  • Root Business Unit: Created automatically when the Dataverse environment is provisioned. Cannot be deleted.
  • Child Business Units: Represent regional divisions or business departments. Users belong to exactly one business unit.
  • Modern Matrix Ownership: Allows users in one BU to own records in another BU via security role assignments.

Team Collaboration Types

  • Owner Team: Can own records in Dataverse. Security roles can be assigned directly to the team.
  • Access Team: Cannot own records. Dynamically shares specific records with team members using an Access Team Template (Read, Write, Append privileges). Ideal when sharing fluctuates rapidly.

📱 Model-Driven vs Canvas Apps: Architecture & Power Fx

Model-Driven Apps

Component-focused design driven entirely by the Dataverse metadata model:

  • Navigation: Modern App Designer configuring Areas, Groups, and SubAreas.
  • Forms: Main, Quick Create (fast side-panel creation), Quick View (read-only related record data), Card.
  • Views: Public views, System views, Personal views with customizable column ordering and sorting.

Canvas Apps & Power Fx

Pixel-perfect custom UI connecting to 1,000+ connectors:

  • Delegation: Offloading query execution to the server data source. Non-delegable functions (e.g. complex text matching or non-indexed operations) trigger delegation warnings and limit evaluation to the first 500–2,000 records.
  • Collections: In-memory client-side data caches populated via ClearCollect(colOrders, Orders).

Advanced Power Fx Patterns

// High-performance concurrent loading of master data on App Start
Concurrent(
    ClearCollect(colCustomers, Filter(Accounts, 'State/Province' = "London")),
    ClearCollect(colProducts, Filter(Products, StateCode = 'StateCode (Products)'.Active)),
    ClearCollect(colCurrencies, Currencies)
);

// Transactional Patch operation with error verification
UpdateContext({locNewRecord:

        Accounts,

            name: txtAccountName.Text,

        }

⚡ Power Automate Cloud Flows & Process Governance

Power Automate provides enterprise workflow automation with automated, instant, and scheduled cloud flows.

Enterprise Try-Catch Pattern: Group critical actions inside a Scope named Scope - Try. Add a following Scope named Scope - Catch, and configure its Run After condition to execute only if Scope - Try has failed, timed out, or is skipped. Inside Catch, log errors to Dataverse and alert administrators via Teams.

📝 Realistic PL-200 Practice Scenarios

Scenario 1: Delegation Warning in Canvas Apps

A consultant develops a Canvas App connected to an Azure SQL database containing 350,000 inventory transaction records. The app uses the following formula to display items: Filter(Transactions, StartsWith(TransactionCode, "TX-2026") && Quantity > 50). Users complain that only a small subset of matches appear.

Question: What is causing this behavior and how can it be resolved?

  • A) Canvas apps cannot query Azure SQL databases; data must be migrated to SharePoint lists.
  • B) A non-delegable formula causes Power Apps to pull only the first 500 (or up to 2,000) records locally for filtering. Resolve by using delegable predicates supported by the SQL connector or pre-filtering using a SQL View / Stored Procedure.
  • C) Increase the browser cache limit in Microsoft Edge.
  • D) Convert the app into a Model-Driven app; Canvas apps have a strict 2,000 record maximum limit.
Click to view Answer & Detailed Technical Rationale
Correct Answer: B (Formula non-delegability limits processing to local record limit)

Detailed Analysis:

  • Option B is CORRECT: In Power Apps Canvas apps, if a query expression cannot be delegated to the underlying server engine, Power Apps fetches only the initial record batch (default 500, configurable up to 2,000) and executes the filter locally in client memory. Records beyond 2,000 are completely ignored. To resolve, ensure all functions are delegable for that specific connector, or create a SQL View / Stored Procedure in Azure SQL to execute server-side and return only the pre-filtered result set.
  • Option A is INCORRECT: Azure SQL is a premier enterprise connector for Power Apps with far superior delegation capabilities compared to SharePoint.
  • Option C is INCORRECT: Browser cache does not govern Power Apps connector query delegation.
  • Option D is INCORRECT: Canvas apps can query millions of records provided formulas are fully delegable.
