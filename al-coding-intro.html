Intro to AL Coding in Dynamics 365 Business Central

Modern Business Central development guide: Extensions 2.0, VS Code AL Language, Event Subscribers, Table/Page Extensions, and Docker Sandboxes.

💻 Modern Business Central Extensibility

In modern Dynamics 365 Business Central, customization has evolved from modifying base C/AL source code to the Extensions 2.0 model. All customizations are written in AL Language using Visual Studio Code, packaged into isolated .app files that subscribe to events without modifying standard platform code.

Key Benefit of Extensions: Zero-friction monthly and major platform updates from Microsoft, as custom code lives in its own sandboxed layer.

🛠️ Development Environment Setup

1. Visual Studio Code

Install VS Code and the official AL Language extension from the Visual Studio Marketplace.

2. Local Docker Container

Run local BC artifacts in Docker using PowerShell BcContainerHelper for rapid compile and debug loops.

3. Project Manifest

Configure app.json (App ID, Name, Publisher, Dependencies) and launch.json (Dev Server Endpoint).

🧱 Core AL Objects & Syntax

Table & Table Extension

Define new relational database schemas or extend existing standard Business Central tables with new fields.

table 50100 "Loyalty Tier"
{
    DataClassification = CustomerContent;
    
    fields
    {
        field(1; "Tier Code"; Code[20])
        {
            Caption = 'Tier Code';
            NotBlank = true;
        }
        field(2; "Discount %"; Decimal)
        {
            Caption = 'Discount %';
            MinValue = 0;
            MaxValue = 100;
        }
    }
    keys
    {
        key(PK; "Tier Code") { Clustered = true; }
    }
}

Page Extension

Extend standard Business Central UI cards, lists, and factboxes by adding controls, actions, or group layouts.

pageextension 50101 "CustomerCardExt" extends "Customer Card"
{
    layout
    {
        addafter(General)
        {
            group(Loyalty)
            {
                Caption = 'Loyalty & Rewards';
                field("VIP Tier"; Rec."VIP Tier")
                {
                    ApplicationArea = All;
                    ToolTip = 'Specifies customer VIP status.';
                }
            }
        }
    }
}

⚡ Event-Driven Programming in AL

Instead of modifying core posting code, AL developers subscribe to integration and business events published by Microsoft:

codeunit 50105 "Loyalty Event Handler"
{
    [EventSubscriber(ObjectType::Table, Database::"Sales Header", 'OnAfterInsertEvent', '', true, true)]
    local procedure ApplyVipDiscountOnOrderCreated(var Rec: Record "Sales Header")
    var
        Cust: Record Customer;
    begin
        if Cust.Get(Rec."Sell-to Customer No.") then begin
            if Cust."VIP Tier" <> '' then begin
                // Execute business logic without touching core Sales Post logic
                Message('VIP Customer %1 detected! Loyalty rules applied.', Cust.Name);
            end;
        end;
    end;
}

📋 Essential AL Developer Best Practices

  • Always use SetRange() over SetFilter(): SetRange() is heavily optimized by SQL Server for index seeks.
  • Use CalcFields() wisely: FlowFields are calculated on demand; only call CalcFields() on fields you specifically need.
  • Clean Transactions: Never perform UI interactions (e.g., Confirm() or Dialog()) inside database write transactions or automated background jobs.
