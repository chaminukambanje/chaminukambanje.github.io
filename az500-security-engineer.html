🛡️ Microsoft Sentinel: KQL Analytics & Automated Threat Hunting

// KQL Rule: Detect Brute Force Login followed by Successful Azure Portal Sign-in
let timeframe = 1h;
let failed_threshold = 10;
SigninLogs
| where TimeGenerated >= ago(timeframe)
| where ResultType in ("50126", "50053") // Invalid password / locked account
| summarize FailedCount = count() by UserPrincipalName, IPAddress, bin(TimeGenerated, 5m)
| where FailedCount >= failed_threshold
| join kind=inner (
    SigninLogs
    | where TimeGenerated >= ago(timeframe)
    | where ResultType == "0" // Successful login
    | project SuccessTime = TimeGenerated, UserPrincipalName, IPAddress, AppDisplayName
) on UserPrincipalName, IPAddress
| where SuccessTime > TimeGenerated
| project SuccessTime, UserPrincipalName, IPAddress, FailedCount, AppDisplayName

📝 Realistic AZ-500 Practice Scenarios

Scenario 1: Securing Azure PaaS Storage from Data Exfiltration

A financial organization mandates that backend Azure Storage accounts containing customer PII must be completely inaccessible from the public internet. Furthermore, application compute instances running inside Azure VNets must access storage through private IP addresses, guaranteeing that all traffic remains strictly on the Microsoft backbone network.

Question: Which architecture provides the highest security isolation?

  • A) Storage Account Firewall configuring public IP allowlists
  • B) Azure Private Endpoints (Private Link) with private DNS zone integration
  • C) Service Endpoints without disabling public network access
  • D) Encrypting blobs with customer-managed keys (CMK)
Click to view Answer & Detailed Technical Rationale
Correct Answer: B (Azure Private Endpoints with private DNS zone integration)

Detailed Analysis:

  • Option B is CORRECT: Azure Private Endpoints assign a dedicated private IP address from your VNet subnet to the Storage account service. By disabling public network access entirely, the storage account's public DNS name resolves to the private IP (via Azure Private DNS Zones). Traffic never leaves the private virtual network, completely preventing data exfiltration to unauthorized storage accounts.
  • Option A is INCORRECT: Public IP allowlisting leaves the public storage endpoint exposed to the internet.
  • Option C is INCORRECT: Service Endpoints route traffic across the Microsoft backbone, but the storage account still maintains a public IP address.
  • Option D is INCORRECT: CMK encrypts data at rest but does not restrict network perimeter transmission.
