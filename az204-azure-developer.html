⚡ Azure Functions: Isolated Worker & Output Bindings

using System.Net;
using Microsoft.Azure.Functions.Worker;
using Microsoft.Azure.Functions.Worker.Http;
using Microsoft.Extensions.Logging;

namespace Contoso.Serverless
{
    public class OrderProcessingFunction
    {
        private readonly ILogger _logger;

        public OrderProcessingFunction(ILoggerFactory loggerFactory)
        {
            _logger = loggerFactory.CreateLogger();
        }

        [Function("ProcessOrderQueueItem")]
        [CosmosDBOutput("OrdersDB", "ProcessedOrders", Connection = "CosmosDBConnection", CreateIfNotExists = true)]
        public OrderRecord Run(
            [ServiceBusTrigger("order-intake-queue", Connection = "ServiceBusConnection")] OrderIncomingMessage incomingOrder)
        {
            _logger.LogInformation("Processing incoming order: {OrderId}", incomingOrder.OrderId);

            return new OrderRecord
            {
                id = incomingOrder.OrderId,
                CustomerName = incomingOrder.CustomerName,
                TotalAmount = incomingOrder.Amount,
                ProcessedAtUtc = DateTime.UtcNow,
                Status = "VERIFIED"
            };
        }
    }

    public record OrderIncomingMessage(string OrderId, string CustomerName, decimal Amount);
    public record OrderRecord
    {
        public string id { get; set; }
        public string CustomerName { get; set; }
        public decimal TotalAmount { get; set; }
        public DateTime ProcessedAtUtc { get; set; }
        public string Status { get; set; }
    }
}

📨 Messaging Decision Matrix: Service Bus vs Event Grid vs Event Hubs

Service Type & Model Optimal Enterprise Use Case
Azure Service Bus High-Value Enterprise Messaging (Pull). Queues & Topics/Subscriptions. Financial transactions, order fulfillment, FIFO guaranteed sessions, duplicate detection, dead-lettering.
Azure Event Grid Reactive Event Distribution (Push-Push). Discrete events. Reacting to Azure resource state changes (e.g. Blob created, VM started) triggering Azure Functions or webhooks.
Azure Event Hubs Big Data Telemetry Streaming (Pull/Partitioned Consumer Groups). High-throughput ingestion (millions of events/sec) from IoT sensors or web clickstreams into Data Lake.

📝 Realistic AZ-204 Practice Scenarios

Scenario 1: Cosmos DB Partition Key Selection

A developer is building an e-commerce order tracking API on Azure Cosmos DB using the NoSQL API. The system stores 20 million order documents per year. Queries frequently look up orders by OrderId or list orders for a specific CustomerId. The database experiences heavy write workloads evenly distributed throughout the day.

Question: Which column represents the optimal Partition Key?

  • A) OrderStatus (e.g., 'Pending', 'Shipped', 'Delivered')
  • B) CustomerId
  • C) OrderYear (e.g., '2026')
  • D) ShippingPostalCode
Click to view Answer & Detailed Technical Rationale
Correct Answer: B (CustomerId)

Detailed Analysis:

  • Option B is CORRECT: An effective partition key requires high cardinality and an even distribution of storage and request units (RUs). CustomerId has millions of distinct values, preventing hot partitions, and ensures all orders for a customer reside in the same logical partition, allowing single-partition reads.
  • Option A is INCORRECT: OrderStatus has very low cardinality (3–5 values). All orders would be funneled into 3–5 physical partitions, causing massive hot partition throttle errors (HTTP 429).
  • Option C is INCORRECT: OrderYear funnels all writes for an entire year into a single hot partition.
  • Option D is INCORRECT: Postal codes exhibit severe geographic skew.
