🔢 NumPy Architecture: Strides, Memory Layout & Vectorization

NumPy provides the high-performance backbone of scientific computing in Python. Understanding NumPy at a systems level requires mastering its memory layout, strides, universal functions (ufuncs), and memory views.

1. Contiguity and Strides Explained

An ndarray is a continuous block of physical memory combined with metadata describing how to interpret it: data type (dtype), shape, and strides (the number of bytes to step in each dimension to reach the next element).

Shape: (3, 4), Dtype: float64 (8 bytes per item) C-Contiguous (Row-Major - Default in C and Python): Row 0: [0, 1, 2, 3] ──► Stride: (32, 8) Row 1: [4, 5, 6, 7] ──► To move 1 row down = jump 32 bytes (4 * 8) Row 2: [8, 9, 10, 11]──► To move 1 col right = jump 8 bytes (1 * 8) Fortran-Contiguous (Column-Major - Used in Fortran & R): Col 0: [0, 4, 8] ──► Stride: (8, 24) Col 1: [1, 5, 9] ──► To move 1 col right = jump 24 bytes (3 * 8) 
import numpy as np

# Create an array of shape (10000, 10000) of 64-bit floats (800 MB)
arr_c = np.ones((10000, 10000), dtype=np.float64, order='C')
arr_f = np.ones((10000, 10000), dtype=np.float64, order='F')

# Performance benchmark: Row-summing on C-ordered array vs Column-ordered array
# Row iteration on C-array is CPU cache-line friendly (L1/L2 hits)
# %timeit arr_c.sum(axis=1)  --> ~28 ms
# %timeit arr_f.sum(axis=1)  --> ~185 ms (6x slower due to CPU cache misses!)

2. Broadcasting Semantics

Broadcasting allows element-wise operations on arrays of different shapes without copying data in memory. Dimensions are compatible when:

  1. They are equal, OR
  2. One of them is 1.

🐼 High-Performance Pandas: Memory Optimization & Pipelines

Standard Pandas workflows often crash due to out-of-memory errors on large tabular datasets. Production data pipelines require proactive dtype downcasting and vectorized transformations.

1. Memory Optimization Function

import pandas as pd
import numpy as np

def optimize_dataframe_memory(df: pd.DataFrame, verbose: bool = True) -> pd.DataFrame:
    '''Downcasts numeric types and converts repeated strings to Categorical.'''
    start_mem = df.memory_usage(deep=True).sum() / 1024**2
    
    for col in df.columns:
        col_type = df[col].dtype
        
        if col_type != object and not pd.api.types.is_categorical_dtype(col_type):
            c_min = df[col].min()
            c_max = df[col].max()
            
            # Downcast integers
            if str(col_type).startswith('int'):
                if c_min > np.iinfo(np.int8).min and c_max < np.iinfo(np.int8).max:
                    df[col] = df[col].astype(np.int8)
                elif c_min > np.iinfo(np.int16).min and c_max < np.iinfo(np.int16).max:
                    df[col] = df[col].astype(np.int16)
                elif c_min > np.iinfo(np.int32).min and c_max < np.iinfo(np.int32).max:
                    df[col] = df[col].astype(np.int32)
                elif c_min > np.iinfo(np.int64).min and c_max < np.iinfo(np.int64).max:
                    df[col] = df[col].astype(np.int64)
            # Downcast floats
            else:
                if c_min > np.finfo(np.float32).min and c_max < np.finfo(np.float32).max:
                    df[col] = df[col].astype(np.float32)
        elif col_type == object:
            # If cardinality is low, convert to Categorical
            num_unique = df[col].nunique()
            num_total = len(df[col])
            if num_unique / num_total < 0.5:
                df[col] = df[col].astype('category')
                
    end_mem = df.memory_usage(deep=True).sum() / 1024**2
    if verbose:
        print(f"Memory reduced from {start_mem:.2f} MB to {end_mem:.2f} MB (-{(1 - end_mem/start_mem)*100:.1f}%)")
    return df

🌍 Atmospheric & Earth Observation Data with Xarray & NetCDF

Climate and earth observation data at national research centers and supercomputing facilities are stored in multidimensional, self-describing NetCDF and GRIB formats. xarray introduces labels in the form of dimensions, coordinates, and attributes on top of raw NumPy-like multidimensional arrays.

Analyzing ERA5 Reanalysis Atmospheric Data

import xarray as xr
import numpy as np

# Open multidimensional atmospheric dataset lazily using Dask
ds = xr.open_mfdataset(
    "/data/climate/ecmwf-era5/data/oper/an_sfc/2024/*/*.nc",
    parallel=True,
    chunks={"time": 720, "latitude": 180, "longitude": 180}
)

# Inspect dataset metadata
print(ds)

# 1. Coordinate slicing (Select European domain over July 2024)
euro_temp = ds['2t'].sel(
    time=slice('2024-07-01', '2024-07-31'),
    latitude=slice(70.0, 35.0),    # ERA5 lat is decreasing
    longitude=slice(-15.0, 30.0)
)

# 2. Convert from Kelvin to Celsius
euro_temp_c = euro_temp - 273.15
euro_temp_c.attrs['units'] = 'degC'

# 3. Compute spatial mean temperature time series weighted by latitude cosine
weights = np.cos(np.deg2rad(euro_temp_c.latitude))
weights.name = "weights"
weighted_temp = euro_temp_c.weighted(weights).mean(dim=["latitude", "longitude"])

# 4. Compute daily max temperature and locate heatwaves
daily_max = weighted_temp.resample(time='1D').max()
print("Top 3 warmest days in Europe July 2024:")
print(daily_max.to_series().nlargest(3))

2. Production PySpark ETL with Delta Lake Time Travel

from pyspark.sql import SparkSession
from pyspark.sql.functions import col, to_date, sum as _sum, avg, current_timestamp
from delta.tables import DeltaTable

# Initialize SparkSession with Delta Lake extensions
spark = (
    SparkSession.builder
    .appName("ClimateTelemetryPipeline")
    .config("spark.sql.extensions", "io.delta.sql.DeltaSparkSessionExtension")
    .config("spark.sql.catalog.spark_catalog", "org.apache.spark.sql.delta.catalog.DeltaCatalog")
    .config("spark.sql.shuffle.partitions", "200")
    .getOrCreate()
)

# 1. Read raw IoT sensor streaming/telemetry logs
raw_df = (
    spark.read.format("parquet")
    .load("abfss://raw-data@datalake.dfs.core.windows.net/iot_telemetry/2026/*/*.parquet")
)

# 2. Clean, cast, and partition data
curated_df = (
    raw_df
    .filter(col("reading_status") == "VALID")
    .withColumn("reading_date", to_date(col("event_timestamp")))
    .withColumn("ingestion_time", current_timestamp())
    .repartition("reading_date")
)

# 3. Write as Gold Delta Table with ACID guarantees
delta_path = "abfss://gold-data@datalake.dfs.core.windows.net/delta/sensor_aggregates"
(
    curated_df.write
    .format("delta")
    .mode("append")
    .partitionBy("reading_date")
    .save(delta_path)
)

# 4. Perform Delta Lake Upsert (MERGE INTO) to handle idempotency
gold_table = DeltaTable.forPath(spark, delta_path)
gold_table.alias("tgt").merge(
    curated_df.alias("src"),
    "tgt.sensor_id = src.sensor_id AND tgt.event_timestamp = src.event_timestamp"
).whenMatchedUpdateAll(
).whenNotMatchedInsertAll(
).execute()

# 5. Query Time Travel snapshot (Auditing previous state)
historical_snapshot = (
    spark.read.format("delta")
    .option("versionAsOf", 2)
    .load(delta_path)
)
print(f"Historical record count at Version 2: {historical_snapshot.count()}")

🧪 Production ML Pipelines with Scikit-Learn & MLflow

Building reliable, leakage-free machine learning systems requires strict decoupling of feature transformations using ColumnTransformer and unified Pipeline objects tracked by MLflow. 

import mlflow
import mlflow.sklearn
from sklearn.model_selection import train_test_split, GridSearchCV
from sklearn.pipeline import Pipeline
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.metrics import classification_report, roc_auc_score

# 1. Define Column Types
numeric_features = ['temperature', 'pressure', 'humidity', 'wind_speed']
categorical_features = ['sensor_model', 'geographic_region', 'power_mode']

# 2. Build Preprocessors
numeric_transformer = Pipeline(steps=[
    ('imputer', SimpleImputer(strategy='median')),
    ('scaler', StandardScaler())
])

categorical_transformer = Pipeline(steps=[
    ('imputer', SimpleImputer(strategy='constant', fill_value='missing')),
    ('encoder', OneHotEncoder(handle_unknown='ignore', sparse_output=False))
])

preprocessor = ColumnTransformer(transformers=[
    ('num', numeric_transformer, numeric_features),
    ('cat', categorical_transformer, categorical_features)
])

# 3. Create Full ML Pipeline
full_pipeline = Pipeline(steps=[
    ('preprocessor', preprocessor),
    ('classifier', HistGradientBoostingClassifier(random_state=42))
])

# 4. Train with MLflow Experiment Tracking
mlflow.set_experiment("Atmospheric_Fault_Detection")

📝 High-Performance Computing Coding Scenarios

Scenario 1: NumPy Memory Leak & Slice Views

A data scientist loads a 50 GB seismic survey dataset using NumPy: full_data = np.fromfile('survey.dat', dtype=np.float32). They extract a small 10 KB subset: sample = full_data[:2500] and delete the original: del full_data. However, Python's memory usage does not drop by 50 GB.

Question: What causes this memory retention, and how is it resolved?

  • A) The garbage collector is disabled; call gc.collect().
  • B) Basic slicing returns a memory view sharing the original array's memory buffer; use sample = full_data[:2500].copy().
  • C) NumPy arrays cannot be deallocated until Python process termination.
  • D) The array must be converted to a Python list before deletion.
Click to view Answer & Detailed Technical Rationale
Correct Answer: B (Basic slicing returns a memory view; use .copy())

Detailed Analysis:

  • Option B is CORRECT: In NumPy, basic slicing creates a view whose .base attribute references the original large 50 GB memory buffer. As long as sample exists in scope, reference counting prevents Python/NumPy from deallocating the underlying 50 GB block. Calling .copy() allocates a dedicated 10 KB buffer, detaching from the base array and allowing immediate reclamation.
  • Option A is INCORRECT: Reference counting handles deallocation immediately unless there are circular references; gc.collect() will not release memory still referenced by sample.base.
  • Option C is INCORRECT: NumPy arrays are standard C-allocated memory blocks released when reference counts reach zero.
  • Option D is INCORRECT: Converting to a Python list would dramatically increase memory overhead.
