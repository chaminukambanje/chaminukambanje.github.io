🧪 Azure ML v2 Python SDK: Architecture & Managed Endpoints

from azure.ai.ml import MLClient
from azure.ai.ml.entities import ManagedOnlineEndpoint, ManagedOnlineDeployment, Model, Environment
from azure.identity import DefaultAzureCredential

# 1. Connect to Azure ML Workspace
ml_client = MLClient(
    DefaultAzureCredential(), 
    subscription_id="00000000-0000-0000-0000-000000000000",
    resource_group_name="rg-datascience-prod",
    workspace_name="aml-prod-workspace"
)

# 2. Define Production Managed Online Endpoint
endpoint_name = "fraud-detection-endpoint"
endpoint = ManagedOnlineEndpoint(
    name=endpoint_name,
    description="Real-time inferencing endpoint for credit card fraud classification",
    auth_mode="key"
)
ml_client.online_endpoints.begin_create_or_update(endpoint).result()

# 3. Deploy Model with Blue/Green Safe Rollout
blue_deployment = ManagedOnlineDeployment(
    name="blue",
    endpoint_name=endpoint_name,
    model=Model(path="./models/fraud_v1/"),
    environment=Environment(image="mcr.microsoft.com/azureml/openmpi4.1.0-ubuntu20.04:latest"),
    instance_type="Standard_DS3_v2",
    instance_count=2
)
ml_client.online_deployments.begin_create_or_update(blue_deployment).result()

# Route 100% traffic to blue
endpoint.traffic = {"blue": 100}
ml_client.online_endpoints.begin_create_or_update(endpoint).result()
print("Managed endpoint and Blue deployment live!")

📝 Realistic DP-100 Practice Scenarios

Scenario 1: Blue/Green Model Deployment & Traffic Shifting

A data science team trains a new iteration of a customer churn model (version 2) with improved accuracy. They want to test the new model in production by routing 10% of real live traffic to version 2 while keeping 90% on the existing version 1 model. If error rates remain normal after 48 hours, they will route 100% to version 2.

Question: Which Azure ML feature supports this traffic routing pattern natively?

  • A) Azure API Management URL rewrite policies
  • B) Managed Online Endpoints with Blue/Green Deployments and percentage traffic allocation
  • C) Azure Batch Endpoints with round-robin job queues
  • D) Deploying two distinct workspaces and updating DNS records
Click to view Answer & Detailed Technical Rationale
Correct Answer: B (Managed Online Endpoints with Blue/Green Deployments and percentage traffic allocation)

Detailed Analysis:

  • Option B is CORRECT: Azure ML Managed Online Endpoints allow multiple distinct deployments (e.g. blue and green) under a single endpoint URI. Administrators can allocate traffic dynamically using percentage weights (e.g. {"blue": 90, "green": 10}) without changing the client application endpoint URL or API key. Once validation passes, traffic can be shifted to 100% green with zero downtime.
  • Option A is INCORRECT: Azure ML endpoints natively provide native traffic routing without external API Management proxies.
  • Option C is INCORRECT: Batch endpoints are designed for asynchronous offline batch scoring of massive datasets, not low-latency real-time inference.
  • Option D is INCORRECT: Workspace duplication is unnecessary and introduces excessive infrastructure complexity.
